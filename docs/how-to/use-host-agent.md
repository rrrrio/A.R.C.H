# 使用本机主机 Agent

已登录的 A.R.C.H. 会话可以请求本机终端操作。模型使用通用 `terminal_exec` 或
`terminal_shell` 工具；后端在执行前检查当前会话档位、工作目录、完整调用内容和 capability。
这不是语音关键词目录：例如查看 GPU、列出进程或检查项目状态都通过同一工具边界处理。

## 选择权限档位

登录后，页面的“主机 Agent 权限”区域默认显示“协助”。三个档位只限制 Agent 可以请求的
最大范围，不会自行授予更高权限：

- “观察”只允许无网络、只读的 `terminal_exec` 请求；不能请求 shell、写入、Docker 或服务控制。
- “协助”是默认档位；Agent 可以在浏览器中请求特定目录、写入、shell、网络或硬件观察权限。
- “主机操作”允许请求用户服务、进程控制和 Docker capability，但每个请求仍须浏览器确认。

所有工具均以当前普通用户运行。`sudo`、`su`、`doas`、root 权限、namespace/容器逃逸和敏感
凭据目录始终不可用。

## 批准和撤销

每个新调用都会在浏览器中请求确认。批准卡片展示完整 argv 或 shell 脚本、工作目录、
请求的读写级别和 capability。批准并成功完成后，完全相同的调用在该浏览器登录会话中可复用 30 分钟；参数、
脚本、路径、读写级别或 capability 任一变化都会再次请求批准。登录结束、服务重启、过期或点击“撤销”
都会使授权失效。

审批记录只保留当前通用工具调用所需的 argv、工作目录和状态；旧的结构化终端计划字段不再生成或展示。

当本地模型把用户目录写成固定占位值 `/home/user` 时，系统会在 argv 和工作目录中显示并执行当前服务用户的真实 home；批准卡只显示规范化后的实际路径。

工具调用使用低采样的结构化输出：普通本地读取只需提交 argv，`cwd`、读写级别和 capability 均应省略。只有调用确实需要网络、硬件、服务或 Docker 时才声明相应 capability。

Docker capability 即使只运行状态查询也属于高风险主机控制面，因为 Docker socket 能管理容器；只在
“主机操作”档位并经浏览器明确确认后执行。

## 当前边界

读取命令在用户级 systemd 进程隔离中运行，具有隐藏 Home、私有临时目录、无网络、最小设备 allowlist
和 `NoNewPrivileges` 边界。当前不自动执行任何模型调用；浏览器确认不会被“只读”标签取代。硬件查询仅在
调用明确请求 `hardware` capability 时获得 NVIDIA 设备节点。结果会以有界文本返回本轮语音回答；审计只
保留调用元数据、结果 hash 和字节数，不保留标准输出正文。

终端调用成功后，语音回答直接使用其有界标准输出或标准错误，不经过模型二次改写，也不会进入后续对话历史；这样后续询问不会复用过期的主机指标。

自动化覆盖工具协议、精确授权、撤销、浏览器认证、GPU 硬件调用、稀疏大文件排序样例和 Docker 授权边界。
本机 GPU 调用已验证；Docker daemon、麦克风和第二台 LAN 设备仍需要单独设备验收，因此该能力状态为
**implemented; GPU-validated; Docker/device-workflow not validated**。
