# 管理对话人物卡

人物卡用于控制本地助手的口吻、互动方式和少量对话示例。完成后，下一次语音连接会使用所选人物卡；中性助手仍可随时恢复。

## 前提

使用配置的 HTTPS 入口登录，例如 `https://arch.local:8443`。人物卡只影响本地 llama.cpp 的文本生成，不会下载或替换语言模型。需要先按[首次在本机完成一次语音对话](../tutorials/first-local-conversation.md)准备模型。

## 创建人物卡

1. 在工作区导航中打开“对话”。
2. 填写名称、互动方式和说话口吻。内容应描述语气、回复长度和追问方式，不要填入密码、主机命令或未经确认的个人事实。
3. 可添加最多六组“示例用户话语”和“示例回答”。这些示例只用于模仿表达方式，不会成为助手声称发生过的事实。
4. 选择“聊天变化”。“克制”更稳定，“活跃”会增加明确闲聊和追问时的措辞变化；主机状态、资料、命令、搜索和不确定问题仍保持原有低变化工具路径。
5. 点击“保存人物卡”。

保存后，点击列表中的“下次连接使用”。如果语音已经连接，先在语音主界面断开，再手动重新连接；页面不会自动重新申请麦克风权限。

## 编辑、停用或恢复中性助手

点击“编辑”可修改人物卡。取消“在下一次连接时启用此人物卡”会保留内容，但下一次语音连接不会将它加入模型上下文。点击“使用中性助手”会清除选择；已删除的选中人物卡也会自动回到中性助手。

人物卡的内容存放在本地 SQLite 数据库，随本机数据备份一起保留。它不进入待确认记忆、知识库索引或浏览器之外的网络请求。

## 验证与排查

重新连接后，进行一句闲聊并观察助手字幕是否使用指定口吻。每次回答还会由服务端选择 `neutral`、`warm`、`calm` 或 `urgent` 中的一个受限输出标签；它只供语音和数字人输出链路使用，不会显示在字幕中。询问主机时间或 GPU 状态时，仍应出现现有的工具审批流程；人物卡不能绕过该流程。

若“对话”页无法读取人物卡，刷新页面并确认后端健康检查可用。若保存失败，缩短字段内容并确认每组示例的两句话都不为空。
