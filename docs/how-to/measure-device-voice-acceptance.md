# 测量目标设备语音验收

本指南用于在第二台局域网设备上测量真实扬声器的首音时间和人工插话停止时间。完成后可判断 A.R.C.H. 是否满足 `speech-end` 到首个可听音频 p95 不超过 1500 ms，以及用户开始插话到旧回答静音 p95 不超过 250 ms。

## 前置条件

先完成[让局域网设备访问](lan-access.md)：目标设备必须通过 `https://arch.local:8443` 打开登录页、信任本地 CA，并绕过上游代理。服务主机应只运行本次会话；关闭其他占用 GPU 的任务，且不同时运行 `make browser-e2e`。

使用一台有扬声器和麦克风的第二台设备。准备可录制屏幕和环境声音的相机或另一部设备，并保持每次测试的音量、网络位置、浏览器和语音模型配置不变。不要把页面显示的“发送首段音频”或“播放停止”当作可听时间；它们是服务器阶段事件。

## 测量首音

1. 在目标设备登录并连接语音，等待状态显示“可以说话”。
2. 录制屏幕和扬声器声音。说出一条固定短句，并在说完时清楚地停顿。
3. 从录音中标记最后一个用户语音样本为 `speech-end`，标记扬声器首次可辨认的助手音频为 `first-audible`。
4. 计算 `first-audible - speech-end`，单位为毫秒。
5. 用同一条件重复 20 次。若连接、识别或播放失败，记录失败原因，不得把该轮替换为成功样本后宣称 20/20 通过。

## 测量人工插话

1. 让助手开始可听播报，录制屏幕和扬声器声音。
2. 在旧回答仍清楚可听时开始说一条固定短句。
3. 标记用户第一个可听语音样本为 `speech-start`，标记旧回答最后一个可听扬声器样本为 `old-audio-stopped`。
4. 计算 `old-audio-stopped - speech-start`，单位为毫秒。
5. 用同一条件重复 20 次。记录旧回答未停止、过早停止或新回答未开始的轮次。

## 汇总结果

将每组 20 个毫秒值从小到大排序。20 个样本的 nearest-rank p95 是第 19 个值。填写并保留以下记录；不要提交原始人声或私人对话。

```text
test_date:
device:
browser_and_version:
network_location:
voice_profile:

first_audible_ms: [20 values]
first_audible_p50_ms:
first_audible_p95_ms:
first_audible_failures:

barge_in_ms: [20 values]
barge_in_p50_ms:
barge_in_p95_ms:
barge_in_failures:
```

只有首音 p95 不超过 1500 ms、插话停止 p95 不超过 250 ms，且没有未解释的失败轮次时，才能把这两项能力记录为目标设备已验收。未达标时，保留分段事件、录音时间戳和失败原因，先定位 ASR、LLM、TTS、网络或浏览器播放环节，再重复整组测量。

## 离线复查

关闭联网搜索并断开主机的外网出口后，重新完成至少一轮普通对话、记忆查询、知识库查询和允许的本机工具调用。第二台设备仍应通过局域网 HTTPS 工作；任何联网搜索失败都必须显示为工具不可用，不能破坏语音会话。
